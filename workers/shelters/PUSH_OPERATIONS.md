# iPhone PWA Web Push 운영

소개: https://safe-korea-shelter-api.trovapp.workers.dev/intro/ . 실행: /app/ . 소개 URL은 일반 브라우저에서 유지하고 manifest 시작 URL만 앱으로 향합니다. 예전 루트 서비스워커가 소개를 앱으로 바꾸던 코드의 영향을 피하도록 별도 소개 경로와 버전 있는 소개 JS/CSS를 제공합니다.

## 배포된 기능

Apple endpoint만 허용하는 Web Push 암호화(RFC8291)와 VAPID 인증(RFC8292), D1 구독/중복·수신·열기 관리, 별도 동의, 수동 테스트·해제/삭제를 구현했습니다. 서명키는 Worker 안에서 생성하고 공개 API는 공개키만 반환합니다. 정부 API 키는 사용자 승인 후 GOV_ALERT_API_KEY Secret에 등록했습니다. 키/구독 주소/가족 정보/위치는 Git이나 로그에 넣지 않습니다. 구독 정보는 동의 이후 서버에 저장하며 해제 또는 Apple 만료 응답 확인 때 삭제합니다.

Worker의 redirect: error는 지원되지 않으므로 manual로 응답을 검사하고 리다이렉트를 따라가지 않습니다. Node 단위 테스트 외에 실제 workerd 런타임에서 암호화 전송·원천 읽기·리다이렉트 차단을 검사합니다. iPhone에서는 앱을 강제로 여는 대신 알림을 누르면 열리며, 앱이 보이는 상태에서는 인증된 전달 ID를 조회해 대응 화면으로 연결합니다. 커스텀 사이렌/집중 모드 우회를 보장하지 않습니다.

## 현재 실제 경보의 차단 사유

2026-11-02 운영 API에서 `gatewayCode:32`, `source_ip_denied` 확인. 같은 키의 이 Mac 단발 조회는 성공했습니다. Cloudflare 출구 IP가 정부 API 신청의 허용 IP에 포함되지 않은 상태입니다. Secret 등록 성공은 API 접근 승인과 다릅니다. 무료 Workers의 출구 IP를 고정 IP로 가정하지 않습니다. 운영 허용 IP/전달·이용 조건을 제공기관과 확인해야 하며 보안 제한을 몰래 해제하거나 전체 IP 허용으로 바꾸지 않았습니다.

`GOV_ALERT_SEMANTICS_VERIFIED`는 false입니다. 운영 원천 접근, 지역/생성 시각 의미, 분류/누락/지연/정정·해제, 실제 iPhone 알림 동작 검증 후에만 변경합니다. 현재 문자 본문을 전쟁 키워드만으로 재전달하지 않으며 안전/긴급/위급 중 민방공·명확한 발령·2분 이내·정확히 해석되는 지역만 후보로 만듭니다. 지역 ID는 시설 행정코드와 달라 ID 숫자를 재사용하지 않고 공식 지역명을 엄격히 대조합니다. 읍면동 등 모호한 세부 지역은 자동 확대하지 않습니다.

현재 Oracle 사용자 수집기가2분마다 조회하고 서명된 민방공 후보/구조 상태를 Workers에 전달합니다. GOV_ALERT_TRANSPORT=collector이므로 Cloudflare cron은 만료 정리만 하며 정부 API를 직접 조회하지 않습니다. Oracle에도 동일하게 일일900회 예산과 인증/IP/한도 오류6시간 대기가 영속 저장됩니다. 100개 조회에서 전체 건수가 맞지 않으면 발송하지 않습니다. 원천이 100건을 넘는 날의 페이지 수집/허용 호출량 조정은 후속 운영 항목입니다. 소규모 검증용이며 실제 경보 대규모 발송 부하·누락/지연 보장은 검증하지 않았습니다.

## 설치·기기 검증

1. Safari로 소개 링크를 열고 공유 → 더보기(필요한 버전) → 홈 화면에 추가 → 추가. ‘웹 앱으로 열기’가 있으면 켜 둡니다.
2. 아이콘으로 열고 첫 실행 팝업 또는 나의 준비 → 알림 설정에서 지역과 정보 처리 동의를 선택한 뒤 허용합니다. 페이지 방문이나 설치만으로 권한을 요청하지 않습니다.
3. 이 기기 테스트 버튼을 누릅니다. 실제 경보가 아님을 명시한 알림 1개만 보냅니다. 1분에 1회, 자기 등록으로만 요청할 수 있습니다.
4. Apple accepted는 서버 접수입니다. service worker가 표시한 receipt, 사용자의 알림 탭 opened를 별도로 확인합니다. 실제 iPhone 잠금/종료/집중 모드와 통신 복귀를 확인하기 전 기기 전달 완료를 주장하지 않습니다.
5. 알림 끄기는 OS 구독 해제와 서버 등록 삭제를 수행합니다. 브라우저 데이터를 지우기 전에 서버 삭제를 먼저 확인하세요. 관리 토큰을 잃은 기존 구독의 재설정/복구 UX는 추가 확인 대상입니다.

## 재검사

사용자 승인 후 Oracle 키/수집기 배치와 서명 전송 accepted=true를 확인했습니다. 아직 Oracle도 오류32이며 포털 로그인 후 해당 서버 IP 등록이 남았습니다. 원천 IP/권한 해결 뒤 [Oracle 수집기 재검사](../../deployment/alert_collector/README.md)에 따라 --reset-backoff 단발 조회로 확인합니다. 공개 설정 GET으로 Oracle의 원천 조회를 시작하거나 오류 대기를 해제할 수 없습니다. 원천의 원문/키를 출력하지 말고 상태·개수·고정 오류 코드만 기록하세요. 실기기 검증이나 원천 상태 확인을 실제 경보 발송 시험으로 대체하지 않습니다.

검사: npm test / npm run check / npm audit --audit-level=high. 브라우저: scripts/test_pwa_launch.cjs, test_pwa_push.cjs, test_shared_pwa_app.cjs. 푸시 브라우저 시험은 Push API/서버 응답 픽스처이며 APNs 실기기 수신 증거가 아닙니다.
