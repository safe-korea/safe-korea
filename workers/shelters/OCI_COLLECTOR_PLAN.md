# Oracle 수집기 배치 현황 — 2026-11-03

현재 로그인된 Oracle CLI로 기존 도쿄 E2.1.Micro 인스턴스 한 대를 읽기 전용 확인했습니다. 이미 공인 IP와 신뢰된 SSH 호스트 키/연결 키가 있고, 비관리자 Ubuntu 사용자(uid1001)로 접속됩니다. Python3·crontab과 약31GiB 여유 디스크를 확인했습니다. 기존 서비스용 서버이며 추가 VM/유료 자원·요금제 변경 없이 별도 사용자 폴더만 사용합니다. 실제 서버 주소/계정/비밀키는 이 문서에 넣지 않습니다.

배치 폴더: 사용자 홈의 `.local/share/safekor-alert-collector/`. 폴더700, 정부 API·연결 설정600. 기존 서비스와 SSH/방화벽 설정은 변경하지 않았습니다. 기존 `scripts/check_alert_api.py`와 검증된 review 모듈의 단발 조회에 이어 stdlib 수집기를 배치했습니다. 기존 공인 IP를 유지하며, 예약 IP 여부·VM 재생성 이후 주소 유지는 보장하지 않습니다. API 허용 IP에는 이 서버 주소를 등록해야 하며 기존 허용 IP는 지원 범위 안에서 보존합니다. 전체 IP 허용으로 완화하지 않습니다.

사용자가 Oracle에 정부 API 키·수집기 연결 키 보관을 명시 승인했습니다. 정부 키와 HMAC 연결 키는 서버의600 설정에, 연결 키는 Cloudflare Secret에도 보관했습니다. Oracle은 민방공 후보 자료와 구조/완전성 결과만 서명해 Workers에 보냅니다. 일반 재난문자·실종 내용은 내보내지 않습니다. Workers가 HMAC/60초 시각/증가하는 스냅샷/지역/중복을 검증한 뒤 기존 발송 게이트를 거칩니다. 공개 상태에는 원문이 없습니다.

Oracle 사용자 crontab에2분 작업 등록 완료. 기존 작업 보존·동일 블록 재설치 방지·최초 백업을 구현했습니다. 상태 로그는 마지막1회만 덮어써 증가하지 않습니다. SQLite 일일900회 제한과 IP/인증/한도 오류6시간 backoff를 적용합니다. Cloudflare cron은 수집기 모드에서 만료 자료 정리만 하므로 정부 API에 중복 접속하지 않습니다.

현재 실제 검증: Oracle 정부 API는 여전히 오류32(미등록 IP), 그 실패 요약을 Oracle→Cloudflare로 서명 전송하여 accepted=true 확인. 공개 상태 transport=signed_collector 확인. 포털 로그인 세션 만료로 허용 IP 등록이 남았습니다. `GOV_ALERT_SEMANTICS_VERIFIED=false`, 실제 경보 발송 비활성. 정상 원천 조회·분류/지역/지연/이용 조건·실제 기기 전달은 후속 검증입니다. [재검사/중단 방법](../../deployment/alert_collector/README.md).

Oracle Always Free 자원은 유휴 회수될 수 있습니다. 기존 인스턴스를 영구 운영 보장으로 안내하지 않으며 원천 마지막 정상 시각/장애 상태를 유지해야 합니다. 무의미한 CPU 사용으로 무료 정책을 우회하지 않습니다. 기존 서비스의 자원·업무에 영향이 생기면 공용 서버 배치는 중단하고 별도 운영 방안을 확인합니다.
