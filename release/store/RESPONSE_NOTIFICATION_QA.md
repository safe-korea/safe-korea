# 알림 → 대응 화면 연결 QA (2026-11-03)

## 구현한 흐름

- iPhone 설치형 PWA: 사용자가 직접 보내는 테스트 Web Push도 빨간 공습경보 대응 화면으로 연결합니다. 인증된 본인 기기의 `/notice` 조회를 거쳐 Flutter 준비 후 표시합니다. 앱을 보고 있으면 바로 전환하며, 닫혔거나 백그라운드이면 시스템 알림을 눌러 엽니다.
- Android: `나의 준비 → 테스트 알림 → 사이렌으로 대응 화면 테스트`. 권한 허용 후5초 뒤 이 기기에만 로컬 테스트 알림을 표시합니다. 앱 사용 중이면 바로 대응 화면, 백그라운드이면 알림을 눌러 같은 화면을 엽니다. 기존 휴대전화 경보 연결 설정에서도 테스트 화면으로 이동할 수 있습니다.
- 두 플랫폼에서 같은 `CivilAlertScreen`과 실내·실외·차량 행동 안내를 사용합니다. 상단 고정 제목과 별도 안내에 테스트임을 표시합니다. 테스트는 실제 정부 경보로 처리하지 않으며, 유효한 실제 경보 화면을 덮어쓸 수 없습니다.
- 동일한 테스트 알림을 다시 눌러 열 수 있습니다. 실제 경보는 기존 중복 차단을 유지합니다. 테스트 유효기간2분, 만료 시 대응 화면으로 전환하지 않습니다.

## 배포와 한계

PWA는 기존 운영 Worker에 배포했습니다(`5c51bdbf-2995-4216-b64a-48a250cfcfef`). 공개 JS·서비스 워커·Flutter 번들 해시를 대조했습니다. Android 업데이트용 versionCode3 AAB는 JAR 서명 검증을 마친 로컬 후보로 준비했으며, 기존 Play versionCode2 설치본을 자동으로 변경하지 않습니다. Play 업로드·심사·새 버전 제공은 별도입니다.

닫힌 iPhone PWA를 강제로 실행하거나 잠금을 해제하지 않습니다. Android 전체 화면 강제 실행 권한을 추가하지 않습니다. Android의5초 지연 테스트는 실행 중인 앱 프로세스를 이용하므로 발송 전에 강제 종료하면 전달을 보장하지 않습니다. 이후 알림을 눌러 새 프로세스로 여는 처리는 기존 플러그인의 콜드 시작 경로를 사용합니다.

기존 Android 정부 경보 경로는 사용자 동의에 따른 Google/AOSP 시스템 재난문자 앱 연결이며, 이번 작업으로 FCM 서버 푸시가 추가된 것은 아닙니다. 제조사별 실제 호환성은 별도 검증이 필요합니다. 운영 정부 API 자동 발송은 분류·지연·기기 검증 전까지 비활성을 유지합니다. 실제 공습경보 또는 외부 수신자에게 알림을 발송하지 않았습니다.

업데이트 후보: `build/release-candidates/safeKor-1.0.0-3.aab` · [SHA256·배포 검사 기록](../../artifacts/qa/response-notification-release.json).


## 같은 사이렌 추가 (후속 수정)

- PWA 알림 설정의 `테스트 사이렌 켜기 · 앱을 보고 있을 때만`을 켜고 직접 테스트 알림을 보내면, 활성화된 오디오 컨텍스트에서 테스트 알림 수신 시8초 재생합니다. 대응 화면에서도 `사이렌 듣기`·`소리 끄기`를 사용할 수 있습니다. 콜드 시작 또는 브라우저 정책으로 자동 재생이 차단된 경우 직접 듣기 버튼을 누릅니다.
- PWA와 Android는 `android/app/src/main/res/raw/drill_siren.wav`의 동일한8초 파일을 사용합니다. PWA 패키징에서 복사하고 콘텐츠 해시 기반 오프라인 캐시에 포함합니다. 앱 숨김·페이지 종료·대응 화면 이탈 시 웹 재생을 중지합니다. 웹 푸시의 시스템 알림음은 이 파일로 바꾸지 않습니다.
- Android의 `사이렌으로 대응 화면 테스트`는 명시적 버튼 입력 후5초 뒤 소리가 켜진 기존 알림 채널로 발송합니다. 일반 훈련 알림의 소리 선택은 그대로 유지합니다. 실제 청취 결과는 기기 볼륨·알림·무음 설정에 따릅니다.
- 후속 검증: Flutter195개·Worker/오디오62개 통과, analyze/check/format 통과. Chromium·WebKit에서 동일 파일 바이트, 사용자 동작으로 오디오 준비, 수신 시 재생 및 수동 재생/중지 통과. Android UI 검사에서 지연 뒤 `playSound:true`·`drill_siren` 리소스·테스트 payload를 확인했습니다. 이 추가 작업에서 물리 기기 스피커 소리나 실제 정부 수신을 검증한 것은 아닙니다.
- 새 서명 후보: `build/release-candidates/safeKor-1.0.0-4.aab`. 기존 versionCode3 파일은 보존했습니다. Play 업로드 전이며 [새 후보 검사 기록](../../artifacts/qa/response-siren-release.json)에 해시를 남깁니다.
- iPhone PWA는 잠금 화면 위에 앱의 대응 화면을 강제로 띄우거나 사용자 지정 사이렌을 재생할 수 없습니다. [Notifications API](https://notifications.spec.whatwg.org/)는 알림 표시와 플랫폼 소리 관례를 정의하며 사용자 지정 알람 소리 API를 제공하지 않습니다. 앱 안의 Web Audio는 [브라우저 자동 재생 정책](https://developer.chrome.com/blog/autoplay/)을 따릅니다. 이 제한을 우회하지 않습니다.
